Start with the quickstart for a first working app. Continue with **Humans and
Agents** to see one business action shared across the UI and an agent tool.
The other examples cover specific widgets, data models, and deployment paths.

“Public interactions” describes a learning demo's declared access model. The
quickstart and tutorial also deliberately share posts between signed-in users.
For owner-specific data, start with a Workers example or adapt the
[access rules](/building/security/) to your application.

## Run a Repository Example

Use Node.js 24 and the repository's pinned pnpm 11.23.0 for source development.
Clone the repository, install once, then choose one app:

```bash
git clone https://github.com/ZapCircleHQ/zebric.git
cd zebric
pnpm install --frozen-lockfile
pnpm --filter task-tracker... build
pnpm --filter task-tracker dev
```

Open http://localhost:3000. In another terminal at the repository root, populate
the board with `pnpm --filter task-tracker seed`. Follow its README for MCP setup.

For the other Node demos, replace the final two commands with the matching pair:

| Example | Build from the repository root | Run from the repository root |
| --- | --- | --- |
| Blog | `pnpm --filter blog-example... build` | `pnpm --filter blog-example dev` |
| Issue Board | `pnpm --filter issue-board-example... build` | `pnpm --filter issue-board-example dev` |

Run one app at a time on the default port. Each package script runs from its own
example directory, so its local database lives in that directory's `data/`.
Use [CLI options](/reference/cli/) when launching a Blueprint directly.

## Run or Deploy a Workers Example

Workers use Wrangler, explicit D1 migrations, and a local `.dev.vars` file.
From an installed repository, the starter's local setup is:

```bash
cd starters/cloudflare-workers
cp .dev.vars.example .dev.vars
pnpm db:migrate
pnpm dev
```

Open http://localhost:8787/auth/sign-up. For the blog, use `examples/workers-blog`
instead of `starters/cloudflare-workers`. Both directories can also be copied
outside the repo and installed independently; preserve their
`pnpm-workspace.yaml` auth pin.

Their READMEs explain database provisioning, production origin, secret setup,
migrations, and deployment. Continue with the [Cloudflare guide](/run/cloudflare/)
for runtime constraints. For Node hosting, use
[Runtime and Deployment](/run/runtime/) and review its operational requirements.
