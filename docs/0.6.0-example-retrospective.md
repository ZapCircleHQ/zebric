# Zebric 0.6.0 example retrospective

Measured against commit `f023648` before the Phase 7 working-tree migration.
Line counts include comments because comments document security boundaries and
remaining gaps. “Authorization checks” means application-specific TypeScript
checks; declarative blueprint policies are intentionally excluded.

| Example | 0.5 workaround | 0.6 primitive | Code removed | Remaining gap |
|---|---|---|---:|---|
| Dispatch | Workflow guards plus broad `Request.update`; fallback API-key role | Protected fields, commands, relation-aware policy, API-key roles | 0 TS LOC | Audit projection, contextual forms, auth-user lookup |
| Merge Conflict Workflow | TypeScript orchestration and separately modeled approval | Protected reviewer commands and command audit/events | 0 TS LOC | Typed local handlers, durable waits, model/artifact primitives |
| Ridgeline Coffee | Guarded workflows plus broad lifecycle updates | Command-only order/shipment/subscription state and SQL-safe names | 0 TS LOC | Aggregate validation and queryable auth users |
| CRM | Semantic workflows could be bypassed by CRUD; fallback agent role | Unified actor policies and protected lead, opportunity, message, classification, and insight commands | 0 TS LOC | Trusted delegated-user binding and typed provider adapters |
| Idea to Operations | Workflow-only convention for Initiative stage | Command-only lifecycle transitions shared by UI, HTTP, MCP, and workflows | 0 TS LOC | Schedules, aggregate assertions, projections, durable outcomes |

Blueprint size increased because the former implicit workflow convention is now
an explicit, reusable command contract with policy, availability, typed input,
generated UI metadata, audit, and events. This is preferable to minimizing LOC:
generic CRUD can no longer bypass the migrated lifecycle boundaries.

## Remaining P0/P1 framework gaps

- A trusted transport/host contract is still needed to bind an API-key agent to
  a delegating human. The actor and policy model preserve `delegatedBy`, but an
  example must not trust a caller-provided identity header.
- Command definitions currently target existing records. Governed creation of a
  record at a non-default lifecycle state is not a declarative command primitive;
  seed fixtures therefore create safe defaults and restore historical snapshots
  through trusted local fixture SQL.
- Framework audit records are not yet a permission-aware query source for pages.
- Workflow preconditions cannot express cross-record `count`/`exists` aggregates.
- Merge Conflict Workflow still needs registered typed local command handlers,
  durable human waits, model-result provenance, and artifact storage.
- CRM’s provider workflows still need fully configured typed service adapters and
  production credentials for live Google Places, SendGrid, and LLM validation.

## Evaluation

The migration removed broad fallback API-key grants and replaced 47 direct
lifecycle mutations with domain commands. It did not remove TypeScript from the
merge-conflict example because doing so would merely relocate Git, classifier,
and retry logic into an untyped blueprint escape hatch. That friction remains
useful evidence rather than being hidden in example-specific framework code.
